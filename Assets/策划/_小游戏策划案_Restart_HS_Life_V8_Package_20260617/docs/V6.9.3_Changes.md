## 0. 文档说明

本文件是 V6.9.3 主玩法 demo 的设计变更说明，详细记录 V7.0 → V6.9.3 之间的所有设计变更和实现细节。

**V6.9.3 定位**：
- V7.0 文档是**完整策划框架**（覆盖 15 学期/450 关/3 阶段/40 结局/抽卡/卡牌升级等所有系统）
- V6.9.3 是**主玩法 demo 最新版**（聚焦"1 局 = 1 天"的核心循环，验证核心爽点）
- **本文件 = V7.0 与 V6.9.3 demo 之间的桥梁**，记录 demo 实际实现的设计取舍

**变更背景**：
- V6.8 demo 试玩后，主人发现"压力系统"过于复杂，玩家需要理解 5 档压力 + 4 个压力反应
- V6.9 demo 把"压力"重命名为"精力"，从"被动积累"改为"主动消耗"（参考杀戮尖塔的能量系统但更轻量）
- V6.9.2 试玩后，反馈"结算太长/流水没对齐/属性加太多/精力过低没缓冲"等问题
- V6.9.3 试玩后，反馈"还有放弃选项/流水事件没对齐/事件太多/结算没半身像"等问题，做了**第二轮重大重构**

## 1. V6.9.3 全部变更清单（9 大改动）

### 1.1 压力系统 → 精力系统（核心改名，V6.9 实施）

| 维度 | V7.0 旧设计（压力） | V6.9.3 新设计（精力） |
|------|------------------|---------------------|
| 概念 | 压力是被动积累的"负担"（类似杀戮尖塔） | **精力是主动消耗的"燃料"**（更像体力值） |
| 范围 | 0-100+（可超 100） | 0-150（可超 100 表示"超常发挥"） |
| 档位 | **5 档**：0-30/30-60/60-80/80-100/100+ | **4 档**：100+/80+/50+/<50（更简洁） |
| 系数 | 5 档乘数：×1.2/×1.0/×0.85/×0.6/×0.3 | 4 档乘数：×1.2/×1.1/×1.0/×0.8（不设崩溃档） |
| 显示 | 独立 5 维 | **HUD 显眼显示**（💪 充沛/😊 良好/😐 一般/😩 疲惫） |
| 重置 | 每晚清零 | **不重置**，每晚恢复 30% |
| 来源 | 压力卡/事件自然积累 | 选项消耗（破局 15 / 稳进 8 / 放弃 3 / 保守 0） |
| 恢复 | 减压卡 / 睡觉 / 看广告 | 睡觉（30%）/ 流水账 5% 概率自然回 1 点 / 加精力事件（CD 2 局） / 看广告（50% 概率 +30） |
| 惩罚 | 压力 >80 触发"崩溃"事件，>100 直接 game over | 精力 <50 提示"属性减半"，<30 触发"执行偏差"（50% 概率属性反转） |

**改造理由**：
1. 主人试玩 V6.8 demo 后反馈"压力系统太复杂，玩家要记 5 档"
2. "精力"概念比"压力"更直观（"做事消耗精力"是常识）
3. 4 档比 5 档更易记，且取消"崩溃"档（崩溃让游戏节奏崩坏，不适合休闲玩家）
4. "持续不重置 + 每晚 30% 恢复"是 V6.9 主人明确要求——精力有"连续性"，让玩家感觉"昨天没干完的事今天还要操心"

**实现细节**：
- State 字段：`energy:100, dayEnergy:100, energyLog:[], energyHistory:[{e:100,t:0}]`
- 函数：`getEnergyZone(e)` / `getEnergyMult(e)` / `applyEWithEnergy(effects)` / `applyEnergyCost(cost)` / `applyEnergyGain(gain)` / `recoverEnergyOvernight()`
- CSS：`.energy-hud-bar`（HUD 显眼条）+ `.settle-rating .sr-energy`（结算页横排）

### 1.2 1 局 10 事件 → 1 局 5 事件（V6.9.3 改造）

| 项目 | V7.0 旧设计 | V6.9.3 新设计 |
|------|----------|--------------|
| 1 局事件数 | **10 事件** | **5 事件** |
| 1 局时长 | 10 分钟 | **5-10 分钟**（事件 + 流水对半） |
| 每日节奏 | 早操→课间→午饭→体育→晚自习→深夜奇葩（10 事件横跨整天） | 早操（7:30）→ 数学（10:00）→ 午饭（12:30）→ 体育（16:00）→ 晚自习（20:30）= **5 个固定时段** |

**5 个固定事件**（按时间轴固定，不是随机）：
- **7:30 早操**（id: `ev_run`，难度 2，行类）—— 体育委员急报 800 米
- **10:00 数学**（id: `ev_math`，难度 2，思类）—— 数学老师点压轴题
- **12:30 午饭**（id: `ev_lunch`，难度 1，行类）—— 食堂拼桌风波
- **16:00 体育**（id: `ev_pe`，难度 1，行类）—— 体育课三对三
- **20:30 晚自习**（id: `ev_night`，难度 2，思类）—— 班主任突击检查作业

**改造理由**：
- V6.9 试玩反馈"事件出现频率太快，流水账和事件没对齐"
- 5 事件更聚焦，每天 5 个关键选择 + 30+ 条流水背景
- 固定时段让"流水账里加事件按钮"的设计成为可能（玩家知道下一个事件什么时候到）

### 1.3 流水账持续随机 → 流水账时间轴 + 事件按钮（V6.9.3 核心新机制）

| 项目 | V7.0 旧设计 | V6.9.3 新设计 |
|------|----------|--------------|
| 流水账触发 | 流水账持续 + 事件随机插入（V7.0 设计） | **流水账按时间轴 33 条固定** + 5 个事件时间点显示"⚡ 进入事件"按钮 |
| 流水数量 | 不固定（持续跑） | **33 条**（7:00-23:00 跨度 16 小时，间隔 20-40 分钟不等） |
| 事件触发 | 事件随机出现 | 流水账播到事件时间点时，**玩家点击"进入事件"按钮**才进事件 |
| 间隔 | 4 秒/条 | **3-4 秒/条**（按 20-40 分钟换算） |
| 打字机 | 无 | **逐字出现**（1.6s 打字机动画 + 橙色光标） |
| 联动 | 流水账是背景 | **流水账 ↔ 事件时间完全对齐**（7:30 早操事件就嵌在 7:30 流水位置） |
| 事件后回到流水 | 事件结束后回流水 | **选项 → 故事分支（影响后续流水）→ 回流水** |

**新机制关键点**：
- 流水账里**每条带具体时间**（7:00/7:20/7:30/8:00/8:30/9:00/9:40/10:00/10:40/11:00...）
- 33 条流水覆盖 7:00-23:00 不规则 20/30/40 分钟间隔
- 5 个事件在 STREAMS 数组里标 `isEvent:'ev_xxx'`
- 流水账里事件位置显示**红色脉冲按钮** "⚡ 进入事件"（CSS 动画 `eventBtnPulse`）
- 玩家**主动点按钮**才进事件（不是被动弹出）
- 事件完成后回流水账，**选项影响后续 1-2 条流水**（故事分支）

**33 条流水举例**（部分）：
```
7:00  闹钟响了 3 遍你才起床，匆匆忙忙塞了两口面包。
7:20  早自习的铃声响了，你抱着课本跑进教室。
7:30  早操集合哨响了，操场上一片脚步声。[⚡ 早操事件]
8:00  早读是英语，你跟着录音跟读了一会儿。
...
20:30 夜自习课间，教室里突然喧闹起来。[⚡ 晚自习事件]
23:00 宿管查完寝，宿舍安静下来，渐入梦乡。
```

### 1.4 4 选项（破局/稳进/保守/放弃）→ 3 选项（破局/稳进/保守）（V6.9.3 改造）

| 项目 | V7.0 旧设计 | V6.9.3 新设计 |
|------|----------|--------------|
| 选项数 | 4 个 | **3 个**（取消"放弃"） |
| 选项构成 | 破局 / 稳进 / 保守 / **放弃** | 破局 / 稳进 / 保守 + 1 看广告（事件 modal 底部） |
| 看广告 | 补 3 张「灵感」万能卡 | **双功能**：50% 概率精力+30 / 50% 概率补 3 张卡 |

**3 个选项详情**：

| 选项 | 消耗 | 收益 | 设计意图 |
|------|------|------|---------|
| 🎯 **破局** | 思×2 + 行×1，精力-15 | 智+6 / 体+3 / 纪+3 / 心+2 | 最高投入最高回报，差学生也能用 |
| ⚡ **稳进** | 思×1，精力-8 | 智+3 / 体+1 / 纪+2 / 心+1 | 中等投入中等回报 |
| 🤷 **保守** | 无消耗，精力-0 | **随机 1-2 个属性**（60% 概率 -1，40% 概率 +1） | 0 消耗保底，但属性变化小且可能减 |

**改造理由**：
- 主人明确说"没有放弃这个选项"
- 4 选项 → 3 选项更聚焦，玩家长时间盯着屏幕选"4 选 1"心理压力大
- "放弃"是负反馈选项（属性-3/-1/-2/-1 + 精力-3），但实际玩家不傻没人会选，对设计没意义
- 保守 + 随机 + 0 消耗，已经是"放弃"的更优替代

### 1.5 选项影响故事/角色发展（V6.9.3 新增）

**核心改动**：每个事件都加了 `storyBranch` 字段，根据玩家选项 [0/1/2/3] 返回不同的"后续故事"，让选择真的影响走向。

**5 个事件的 storyBranch 示例**：

**ev_run 早操**：
- 选 [0] 跟着节奏跑完全程 → "跑完 800 米后你喘着气坐在操场边，腿有点酸但心情不错。"
- 选 [1] 咬牙冲刺前三 → "你冲到前三名，几个同学对你竖起大拇指，但累得直不起腰。"
- 选 [2] 躲在队伍后面偷懒 → "你躲在队伍后面磨洋工，被体育老师抓个正着，罚跑了 1 圈。"
- 选 [3] 说身体不舒服申请休息 → "你申请休息，体育老师看了看你脸色，同意让你在旁边观察。"

**ev_lunch 食堂**：
- 选 [0] 大方同意并帮他们刷一下 → "你帮他们刷了卡，他们感激地说下次一定还，你心里暖暖的。"
- 选 [1] 委婉说位置有限 → "你委婉拒绝了，他们耸耸肩去找别的位置，场面有点尴尬。"
- 选 [2] 装作没听见继续吃饭 → "你装作没听见，默默吃完了饭，心里有点不安。"
- 选 [3] 开玩笑让他们下次请客 → "你开了个玩笑，他们笑了，说下次请你喝奶茶，气氛很轻松。"

**ev_night 晚自习**：
- 选 [0] 立刻翻书包检查作业 → "你翻书包发现作业都做完了，长舒一口气，自信地等明天检查。"
- 选 [1] 迅速补完最关键的几项 → "你埋头补了 30 分钟，把最重要的几项赶完，累但踏实。"
- 选 [2] 问同桌借作业抄 → "你借了同桌作业快速抄完，心里有点虚但也没别的办法。"
- 选 [3] 心里盘算着怎么跟家长说 → "你盘算着怎么跟家长说，结果越想越烦，决定先睡一觉再说。"

**设计意图**：
- V7.0 的"选项影响"是数值层面（属性±3/±1）
- V6.9.3 增加**叙事层面**的"选项影响"（故事走向 + 角色关系）
- 5 个事件 × 4 个选项 = **20 个不同故事分支**（每个事件都至少有 4 种走向）
- 后续扩展：可以加 NPC 好感度字段，把"借同桌作业"变成"同桌好感 -5，事件后续触发"

### 1.7 精力系统保护机制（V6.9 + V6.9.2 双重保护）

| 触发条件 | 保护机制 | 实现 |
|---------|---------|------|
| 精力 < 50% | **黄色横幅提示**："💡 精力 50% 以下：获得的属性会减少"（只提示 1 次） | CSS `.energy-warn.caution` + `State.lowEnergyTipShown` |
| 精力 < 30% | **红色脉冲横幅**："⚠️ 精力 30% 以下：消耗精力的选项可能执行有偏差（+变-）" | CSS `.energy-warn.danger` + `pulse-warn` 动画 |
| 精力 < 30% | **执行偏差**：破局/稳进/放弃 50% 概率属性反转 | `Math.random()<0.5` 反转 effects 符号 + 事件完成小卡变 ⚠️ 图标 |
| 精力 ≤ 50 且 CD=0 | **加精力事件强制触发**："🎁 收到一份小惊喜"，3 选项都回精力 | `getNextEvent` 判断 + `ev.isEnergyEvent=true` |
| 加精力事件 3 选项 | +25 / +10 / +15 精力 + 少量属性（心理/纪律） | 独立 `executePlay` 分支 |
| 加精力事件 CD | **2 局**内不重复触发 | `State.energyEventCD=2`，每完成一局 CD-1 |
| 精力耗尽 | 玩家只能选保守（0 消耗）或看广告 | `checkOptionRequire` 自动判断 |

**保守选项 0 消耗 + 随机属性**（V6.9.2 改造）：
- 不消耗卡牌、不消耗精力
- 随机生成 1-2 个属性变化
- 60% 概率 -1（小幅负向），40% 概率 +1（小幅正向）
- 显示 "🎲 随机属性" 紫光 chip（增加神秘感）
- 即使精力 < 30% 也不反转（保护玩家"安全选项"）

### 1.8 看广告双功能（V6.9.2 改造）

| 项目 | V6.8/V7.0 旧设计 | V6.9.3 新设计 |
|------|-----------------|---------------|
| 触发 | 卡组耗尽时强制 | **卡组没空也能用**（事件 modal 底部"📺看广告"按钮） |
| 功能 | 补 3 张「灵感」万能卡 | **双功能**：50% 概率精力+30 / 50% 概率补 3 张卡 |
| 限制 | 无限制 | **每天 1 次**（`State.dayAdCount`）+ **局内 2 局 CD**（`State.energyAdCD`） |
| 文案 | 固定 | **动态文案**："📺看广告（50%回精力/50%补卡）" / "CD: 2 局" / "明天再用" / "已用" |

**看广告按钮状态机**：
- `State.adUsed`=true → 显示"已用"（disabled）
- `State.dayAdCount>=1` → 显示"明天再用"（disabled）
- `State.energyAdCD>0` → 显示 "CD: N 局"（disabled）
- 否则 → 显示 "📺看广告（50%回精力/50%补卡）"（可点击）

### 1.9 结束流程重构（V6.9.3 核心改造）

**V7.0 旧设计**：10 事件完成 → 流水账收尾 → 立即结算

**V6.9.3 新设计**：5 事件完成 → 推 2-3 条结束流水 → 出结束语"今天最后一缕光熄灭..." → **黑屏转场（月亮漂浮）** → 结算

**结束流程时序**：
```
第 5 个事件完成
  ↓ (0.6s)
自动 push 3 条剩余流水（11:00/11:30/22:30 这些事件后的剩余）
  ↓ (0.8s)
push 最后一条 "今天的最后一缕光熄灭，枕头边传来室友的呼噜声..." (STREAMS_END)
  ↓ (1.2s)
显示黑屏 overlay（CSS .blackout-overlay）：
```
